# Piik 桌面版（Windows x64）

Piik 桌面封装 0.3.0，随包包含官方 Piik 2.5.0，支持同步后续 GitHub / Gitee 正式发布版。
使用 Electron 45 提供独立窗口。
无需安装 Node.js、Go 或打开系统浏览器。本构建不是 Piik 官方发布。

## 直接使用

1. 将压缩包完整解压到可写目录，双击 `Piik Desktop.exe`。
2. 创建房间：在启动页选择「本地房间」或「公网邀请」，点击进入 Piik。
3. UU 联机：双方先进入相同的 UU 组网房间，在「本地房间」中选择 UU 虚拟 IPv4，再发送完整邀请链接。
4. 观看朋友：将完整的 Piik 邀请链接粘贴到窗口顶部，点击「加入朋友」。
5. 本地 HTTPS 邀请首次访问会提示证书，请与房主核对指纹；房主可点击桌面工具栏「证书」查看。

原生分享：点击「开始分享」，选择「程序 / 窗口」或「屏幕」。整屏分享系统声音时，
可在支持的系统上「排除应用声音」，选择外部语音软件，避免朋友听到自己的回声。
房间语音在「互动 → 语音」中开启。不要同时开启分享麦克风和另一条相同的语音输入。

「浏览器」采集按钮在桌面内会打开屏幕/窗口选择器，而非浏览器标签选择器。
该选择器的声音是完整系统声音；按应用音频和排除声音请使用 Piik App 原生采集。
「摄像头」和语音会单独询问设备权限。

左上角返回/启动页/刷新按钮只操作窗口，不会自动结束正在运行的本地房间。
点击关闭按钮或按 Alt+F4 时，默认询问「隐藏到托盘 / 退出程序 / 取消」。
勾选「记住我的选择」后，后续关闭直接执行该行为；可在「窗口 → 关闭窗口选项」修改，
也可通过托盘右键菜单修改。

隐藏到托盘保留窗口与连接，不主动停止房间、采集和语音。单击或双击托盘图标可恢复，
右键可选择「显示主窗口」或「退出 Piik」。再次运行程序也会恢复现有窗口。
「退出 Piik」菜单、Ctrl+Q、托盘退出和更新重启始终执行完整退出，不会被隐藏偏好拦截。
完整退出会结束本机创建的房间、原生采集和临时公网链接。
窗口最小化时保留运行；实际睡眠、断网和电脑锁屏行为取决于系统与 Piik。

启动页中需要“终端按 D 导出”的 App 诊断芯片在桌面版隐藏。房间页面原有的网页诊断与报告
功能保留；本改动不修改官方内核的日志机制。隐藏规则仅应用于本机启动页，仍适用于内核更新后
保持现有界面结构的版本。

所有桌面设置、站点数据和原生配置保存在程序旁的 `Piik-Data`，与 Chrome/Edge、官方 Piik App 分开。
整个目录需要一起保留，不能只复制 EXE。升级前先退出，在新目录中保留 `Piik-Data`。
程序未进行商业代码签名，Windows 可能显示未知发布者。

## 同步 GitHub 更新

启动后会自动检查 `TNTcraftHIM/Piik` 的最新正式 Release。也可以点击工具栏「更新」，
或选择「帮助 → 检查 Piik 更新」。检查失败不会影响当前房间，点击「重试更新」即可重试。

工具栏的「更新源」可以选择「自动选源」「GitHub」或「国内镜像」。国内镜像为
`https://gitee.com/TNTcraftHIM/Piik`，可以独立检查版本、下载安装，不必先连接 GitHub。
自动模式优先 GitHub，失败后切换 Gitee；手动选择国内镜像时，仅通过 Gitee 检查和下载。
更新源会记住，下次启动仍然使用你的选择。

发现新版后，点击「有更新」查看版本和说明，再选择「下载更新」。下载期间保持现有版本运行；
下载完成后可选择「重启并更新」或「稍后」。选择稍后时，下次正常启动自动应用已验证的更新。
重启会结束当前本机房间、屏幕分享和语音；更新不会在分享过程中强制重启。

下载完整官方 Windows x64 App，校验发布方提供的 SHA-256，检查组件完整性并实际启动候选内核
验证接口与版本后，才标记为可安装。GitHub 使用附件 digest；Gitee 使用发布说明中的校验值与
`piik-source` 源码标识，并与安装包和启动后的版本交叉核对。缺少校验信息时不安装。

更新版本与旧版本分开保存于 `Piik-Data/updates`。切换前备份原生配置；新版启动失败时恢复旧版及配置。
保留当前和上一内核，后续启动清理更早的更新。下载失败、取消或校验失败均不替换当前版本。
原 Piik 界面中的官方 Windows App 下载入口，也会转交桌面版更新流程处理。

同步范围包括官方发布包中的 Web 界面、Go 房间服务、屏幕采集与原生辅助程序。
不会自动编译 `main` 上未发布的提交，也不会更新这个社区桌面外壳或 Electron；外壳功能和 Electron
安全更新仍需替换桌面版安装包，并保留 `Piik-Data`。如果后续 Piik 改变桌面依赖的启动接口，验证会
拒绝该更新，需先升级桌面外壳。

## 开发与打包

需要 Windows x64 和 Node.js 24+，从仓库根目录执行：

```powershell
npm --prefix desktop ci
npm --prefix desktop run prepare:electron
npm --prefix desktop run prepare:runtime
npm --prefix desktop test
npm --prefix desktop run smoke
npm --prefix desktop start
npm --prefix desktop run package
```

`prepare:runtime` 从 GitHub 或项目 Gitee 镜像获取固定版本，强制校验 SHA-256 和源码 revision。
它同时从项目所有者复制品牌图标和共享色板，不维护另一份产品样式。
无需重新编译 Go 或原生采集辅助程序。使用当前发布的完整官方运行时，并保留其许可证。
产物位于 `build/desktop-package/Piik Desktop-win32-x64`。

桌面只拥有窗口、设备权限、邀请导航和后台进程生命周期。Piik 官方 Go 服务仍然拥有
房间权限、原生采集、语音、网络连接和声音排除。程序通过现有 machine 模式禁用系统浏览器，
打开自身 loopback Site 使启动器保持待选状态，再通过 instance token 核对本机服务并发现启动页。
不会因此访问第三方网站；实际房间启动、设备采集和外部站点授权仍由原有界面明确触发。

公网邀请仍采用原项目的 P2P 媒体链路，桌面窗口本身不会解决运营商 NAT 或提高 UU 带宽。
UU、跨网画面传输和实物麦克风/音频排除应由双方在实际环境验收。
